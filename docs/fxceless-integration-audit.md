# Source-Level Audit: `fxceless/victory-gta6` vs. HUST-VIctory (`hust/phase12-memory`)

**Date:** 2026-11-24  
**HUST Baseline:** `hust/phase12-memory` @ `9e1de7f` (RTX 3070 8 GB VRAM, 32 GB DDR4 RAM, Series S profile, 13 consecutive 150–184 s zero-hang runs, `PeakPrivate ~7.0–7.8 GB`, `PeakGpuLocal ~1.5 GB`)  
**Audited Fork:** `https://github.com/fxceless/victory-gta6` @ `004bf69a` (4 commits on top of upstream `VIctory main` `ffe310eb`: `578d459c`, `6a2d9f99`, `d279e69a`, `004bf69a`; tested on RTX 4070 12 GB / 32 GB RAM / Series X profile, ~24 GB RAM in use)  
**Method:** Read-only GitHub API inspection of commits, diffs, and source files. No upstream/fork branches were fetched or merged, and no code or hardware tests were run during this audit.

---

## Executive Summary & Stability Warning (4/4 GPU Device Loss)

`fxceless/victory-gta6` reaches **lit opening-cutscene rendering and the first playable prologue scene** (characters, textures, sky, sunlit exterior, HUD, pause menu, pad input, 2–4 FPS; shadowed/indirectly lit regions remain black because RT bounce/shadows are off).

**Critical stability finding:** `fxceless`'s own `README.md` reports that its **latest commits lose the GPU device shortly after start in 4/4 runs**, while its first commit **`578d459c` was the last clean tree**. Only three commits sit between `578d459c` and `004bf69a`:

1. **`6a2d9f99`** (`+914` `emit/own_bits.rs`, `+416/-16` `emit/lower.rs`, `+115/-3` `emit/wave.rs`, `+121/-6` `ir.rs`, `+71` `structure.rs`, `+452` `emit/wave64_tests.rs`): Translates 59/64 RT trace programs + irradiance-cache shading and moves 51 shaders off approximate wave64 forms. **Primary suspect for the 4/4 device loss** — newly translated complex compute/trace shaders with `own_bits` lane-mask lowering now execute on the GPU. **Do NOT import `6a2d9f99`.**
2. **`d279e69a`** (`+39/-15` `pipeline/make.rs`, `+3/-3` `pipeline/library.rs`): Makes `VICTORY_PIPELINE_WAIT_MS` configurable and calls `library::note_used(&p.key)` before `p.made.get()`. Mechanically small and safe in isolation, though on `fxceless` it can prewarm a broken `6a2d9f99` pipeline earlier.
3. **`004bf69a`** (`+124/-3` `capture.rs`, `+24` `descriptor/host.rs`, `+12` `emit/host.rs`): Diagnostics/test-only (stencil dump + software adapter test skip).

**Takeaway:** Any selective adaptation into HUST-VIctory must draw **strictly from verified, self-contained fixes in `578d459c` and `d279e69a`**, never from `6a2d9f99`, and must preserve HUST's 8 GB VRAM / low-commit discipline (`PeakPrivate ~7.5 GB` vs. `fxceless`'s `~24 GB`).

## Priority Recommendation: Smallest Fix to Reach Visible Gameplay

To take HUST-VIctory from its current state (**stable 150 s zero-hang runs, runaway shaders fixed, dark `level=1` 3D cutscene**) into **lit 3D opening cutscene + visible first gameplay scene** with minimal blast radius and zero risk of importing `fxceless`'s 4/4 device loss, implement in this exact surgical order:

1. **Wave A — Smallest High-Impact Visual Unlock (3 targeted fixes, ~250–350 LOC total, ~0–4 MB memory):**
   - **1A — Bindless heap `s_buffer_load_dword*` SRV-vs-CBV dispatch** (`lower.rs` + `descriptor/host.rs`): Unblocks `BatchCullMeshlets` / `BatchCullPreSkinnedMeshlets` / `BatchCullBatchCSMeshlets` so indirect mesh draws actually emit world geometry instead of 0 meshlets. *(Preserve HUST's `6409451` `StructuredBuffer` stride math when `stride >= 4`!)*
   - **1C — `image_gather4_l` / `image_gather4_l_o` at explicit mip level** (`lower.rs`, ~60 LOC): Fixes Hi-Z occlusion culling so visible world meshlets aren't culled against mip 0.
   - **1B — `texture::alias` format-aliased placed texture GPU copy** (`texture.rs` + `resource.rs` + `draw.rs`, ~120 LOC): Fixes compute-packed sky, probe, and fog light textures so the 3D scene is **actually lit** instead of `level=1` black.
   - **Validate on RTX 3070** (1 hardware test) to confirm lit 3D opening cutscene and progression into the first gameplay scene!
2. **Wave B — Safe Shader Recovery & Prewarming (~80 LOC, 0 MB):**
   - **1D — Lower implicit-level `image_sample*` outside pixel shaders to `sampleLevel` LOD 0** (`lower.rs`): Recovers hundreds of compute shaders cleanly.
   - **3A — `pipeline/make.rs` prewarm-on-pending + `VICTORY_PIPELINE_WAIT_MS`** (`d279e69a` pattern, ~40 LOC): Eliminates repeat first-frame pipeline drops across launches.
3. **Wave C — CPU Bottleneck Relief (~150 LOC, 0 MB):**
   - **2A — `watch::ask_once` per-submission write-watch coalescing + guard-hole caching** (`watch.rs`): Directly attacks our measured `133 ms/frame` `watches` + `164.4 ms/frame` `MEM_PRIVATE` ring-buffer refresh bottleneck while preserving `b8266dd` and `2326b5e`.
4. **Explicitly Deferred (Do Not Touch Yet):**
   - `6a2d9f99` (`own_bits.rs` / RT trace shaders) — prime suspect for `fxceless`'s 4/4 device loss.
   - `VICTORY_INPLACE` (`inplace.rs`) — locks physical RAM, conflicts with demand-commit & `LATE_WAIT`.
   - `VICTORY_LATE_WAIT` / `VICTORY_RELAY` (`host.rs`) and `VICTORY_CARD_BUFFERS` (`shadow.rs`) — high complexity; only consider after Waves A–C deliver lit gameplay and clean CPU refresh times.
